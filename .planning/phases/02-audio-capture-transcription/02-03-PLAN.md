# Key Context from Research

**Pipeline flow:**
1. Connect WebSocket to OpenAI (ws/connect!)
2. Wait for session.created → session.update sent automatically
3. Wait for session.updated → ready for audio
4. Start pw-record subprocess (audio/start!)
5. Stream audio chunks from pw-record to WebSocket (audio/stream-chunks! + ws/send-audio!)
6. Receive transcription deltas from WebSocket → accumulate in text buffer
7. On stop: kill pw-record, close WebSocket, return accumulated text

**Thread model:**
- Main thread: waits for shutdown signal (Ctrl+C or future toggle signal)
- Audio thread (future): runs audio/stream-chunks! loop
- WebSocket thread: managed by java.net.http internally, calls on-message callbacks

**Text accumulation pattern:**
```clojure
(def text-buffer (atom ""))

;; On delta event:
(swap! text-buffer str delta-text)

;; On completed event:
;; The completed transcript replaces all deltas for that utterance
;; But for simplicity, we can just keep accumulating deltas
```

**Transcription behavior (IMPORTANT from research):**
- Deltas arrive AFTER VAD detects silence, not during speech
- Each speech segment produces one or more deltas followed by a completed event
- The completed event's :transcript field is the final text for that segment
- Multiple segments accumulate as the user speaks in bursts

**Shutdown hook for clean Ctrl+C:**
```clojure
(.addShutdownHook (Runtime/getRuntime)
  (Thread. (fn [] (stop-pipeline!))))
```

               [ok-voice.notify :as notify]))

2. Text buffer and pipeline state:
   ```clojure
   (def ^:private text-buffer (atom ""))
   (def ^:private ready? (atom (promise)))   ;; atom wrapping a promise, so it can be reset per start! call
   (def ^:private pipeline (atom nil))       ;; holds current pipeline for cleanup from callbacks
   ```

3. Function `(start! [api-key])` that:
   - Resets text-buffer to empty string: `(reset! text-buffer "")`
   - Creates a fresh promise: `(reset! ready? (promise))`
   - Connects to OpenAI via ws/connect! with handlers:
     - `:on-ready` — delivers true to the promise via `(deliver @ready? true)`, prints "[ready]" to stderr
     - `:on-delta` — appends delta text to text-buffer atom, prints delta to stdout (no newline) via `(print delta) (flush)`
     - `:on-completed` — prints newline to stdout (segment boundary)
     - `:on-speech-started` — (optional) could print indicator, keep it silent for now
     - `:on-speech-stopped` — (optional) keep silent
     - `:on-error` — prints error to stderr, notifies via notify/error. Also calls `(stop! @pipeline)` to clean up audio process on fatal errors.
     - `:on-close` — prints "[disconnected]" to stderr. Stops audio capture if pipeline is active: `(when-let [p @pipeline] (audio/stop! (:audio-proc p)))`. This prevents zombie pw-record processes when WebSocket drops unexpectedly (Research Pitfall 4).
   - Waits for ready? promise: `(deref @ready? 10000 nil)`
   - If timeout (deref returns nil): notify error "Failed to connect to OpenAI" and return nil
   - Starts audio capture via audio/start!
   - Starts audio streaming in a future: `(future (audio/stream-chunks! audio-proc (fn [chunk] (ws/send-audio! websocket chunk))))`
   - Stores and returns pipeline map: `(let [p {:ws websocket :audio-proc audio-proc :audio-thread audio-future}] (reset! pipeline p) p)`

4. Function `(stop! [pipeline-map])` that:
   - Takes pipeline map from start!
   - If pipeline-map is nil, returns nil
   - Resets pipeline atom to nil: `(reset! pipeline nil)` (prevents double-cleanup from callbacks)
   - Stops audio capture: `(audio/stop! (:audio-proc pipeline-map))`
   - Waits for audio thread to finish: `(deref (:audio-thread pipeline-map) 5000 nil)`
   - Closes WebSocket: `(ws/close! (:ws pipeline-map))`
   - Small delay for final events: `(Thread/sleep 100)`
   - Returns nil

6. Function `(get-text [])` that:
   - Returns current contents of text-buffer atom
   - Call this after stop! to get the full transcription

Do NOT add:
- Toggle mode logic (that's Phase 3)
- Text insertion via xdotool (that's Phase 4)
- Reconnection logic (keep simple for Phase 2)
- State file/PID management (that's Phase 3)
